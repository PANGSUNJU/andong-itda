# 안동잇다 — 기능설명서 작성용 정리

> 팀명 **길잡이** · 서비스명 **안동잇다 (Andong Itda)** · 웹 서비스
> 실측 기준일 **2026-09-18**. 숫자는 전부 배포 코드에 실호출해 얻은 것이다.

---

## 1. 한 문장

> **하회마을 말고 무엇을 볼지 먼저 보여주고, 차 없이 거기 닿는 법까지 함께 답한다.**

### 제출용 서비스 개요 (문단형)

각종 서류의 "서비스 개요" 칸에 쓰는 정본이다. **기획 단계 원문을 실제 만든 것에
맞춰 고쳤다.**

> 안동잇다는 '안동을 잇는다'는 의미로, 흩어진 관광·교통·식도락 정보를 하나로 연결해
> 차가 없어도 안동을 충분히 즐길 수 있게 돕는 안동 특화 여행 정보 웹 서비스.
> 한국관광공사 OpenAPI(국문·영문 관광정보, 기초지자체 중심 관광지, 연관 관광지,
> 관광사진)와 안동시 버스정보 공공 API를 연동해 현 위치 주변 관광지 탐색, 목적지까지
> 가는 실시간 버스 안내와 총 소요시간·돌아오는 편, 낮·밤 도보 코스, 안동 향토음식을
> 한 곳에서 제공하며, 차가 없어서 못 가는 것이 아니라 몰라서 못 갔을 뿐임을
> 알리는 것이 목표.

⚠️ **접수 페이지의 "서비스 개요" 칸은 300자 제한이다. 위 문단이 295자다.**
서술형("~입니다")이 아니라 명사형("~웹 서비스.")으로 끝나는 것도, `5종`이라는 말을
뺀 것도 그 제한 때문이다. 괄호 안에 다섯이 그대로 열거돼 있어 잃는 것이 없다.

**기능설명서 슬라이드 2와 접수 페이지에 같은 문장이 들어간다**(2026-09-20 반영).
심사가 이 개요와 `활용 Open API` 체크박스를 대조하므로 둘은 어긋나면 안 된다 —
여기 열거한 다섯이 체크할 다섯이다.

#### 기획 단계 원문에서 고친 것

| 원문 | 왜 고쳤나 |
|---|---|
| 한국관광공사 OpenAPI(국문 관광정보·**두루누비**·**관광지 집중률** 등) | **둘 다 안 쓴다.** 두루누비는 전수 확인 결과 144코스가 곧 「코리아둘레길」이고 내륙인 안동은 수록 범위 밖이었다(→ ADR-008). 집중률은 LocgoHub `hubRank`로 대체했다 — *"방문 데이터 기반이라 더 직접적"*(`PROJECT-PROMPT.md:342`). 실제 쓰는 5종으로 바꿨다 |
| 여행자가 스스로 **동선을 짜기 편하도록** | 우리가 **순서를 짜주지는 않는다.** "묶음은 코스가 아니다 — 순서도 소요 시간도 말하지 않는다"가 코드·타입·문구·UI 네 겹에 박혀 있다(→ ADR-016·043). 판단 재료를 주는 쪽으로 고쳤다 |
| 관광지별 **실시간 버스 안내** | 그 뒤로 더 갔다. 목적지를 정하면 그쪽 가는 차를 앞으로 당기고, **총 소요시간과 돌아오는 편·막차**까지 답한다 |
| 한 곳에서 제공**하고자 합니다** | 이미 만들었다. 현재형으로 |
| 뚜벅이에게는 필수, **자가용 이용자에게도 유용한** | **자가용 기능이 없다.** 주차 한 줄은 상류 이용안내 값을 옮긴 것뿐이다. 서비스가 실제로 하는 주장으로 대체했다 |

#### 원문에 없었는데 만든 것

영문 전 경로(제안서에선 2단계였다) · 축제 안내(ADR-010에서 뺐다가 ADR-035로 되살림) ·
연관 관광지 `함께 많이 찾는 곳` · 관광사진 보충 · 목적지 검색과 총 소요시간 ·
좌표를 서버로 보내지 않는 원칙(ADR-024).

#### 한 문장으로 줄이면 (PPT 슬라이드 2 · 양식이 1문장을 요구한다)

> 안동잇다는 '안동을 잇는다'는 뜻으로, 무엇을 볼지 먼저 보여주고 차 없이 거기 닿는
> 법까지 이어 주는 안동 특화 여행 정보 웹 서비스입니다.

---

### 풀려는 문제는 둘이다

안동을 검색하면 `렌터카는 필수`가 먼저 나온다. 그런데 차 문제가 풀려도 하나가 남는다
— **"하회마을 말고 뭘 해야 하지?"** 이 둘이 실제 방문을 가로막는 장벽이었다.

사실 하회마을·도산서원·봉정사·병산서원 **네 곳 모두 시내버스가 다닌다.** 문제는
접근성이 아니라 **정보**였다. 관광 정보와 교통 정보가 서로 다른 곳에 있어 여행자가
두 서비스를 오가며 스스로 짜맞춰야 했고, 대부분 그 단계에서 안동을 후보에서 지운다.

### 그래서 만든 것

**관광을 먼저 보여주고, 교통을 붙인다.** 순서가 중요하다 — 버스 앱이 아니라
여행 안내다. 버스는 "거기 갈 수 있다"를 증명하는 수단이다.

## 2. 화면 다섯과 각자의 존재 이유

| 경로 | 이름 | 이 화면이 없으면 |
|---|---|---|
| `/` | **지금 여기** | 지금 선 자리에서 무엇을 할 수 있는지 알 수 없다 |
| `/browse` | **둘러보기** | 안동에 무엇이 있는지 한눈에 볼 곳이 없다 |
| `/spots/[id]` | **관광지 상세** | "여기, 차 없이 갈 수 있나"에 답할 곳이 없다 |
| `/walk` | **걷는 길** | 버스가 끊긴 시간에 남는 선택지가 없다 |
| `/about` | **안내** | 어디서 온 정보인지, 무엇을 모르는지 밝힐 곳이 없다 |

추가로 **축제 팝업**(헤더, 열릴 때만)과 **영문 화면**(`/en/*` 전 경로)이 있다.

### 여행자의 흐름

```
   여행 전                    도착 직후                 이동 중              버스가 끊긴 뒤
  ┌────────┐               ┌────────┐            ┌──────────┐        ┌────────┐
  │둘러보기 │──관광지 고름──▶│  상세   │──"가기"──▶│ 지금 여기 │        │ 걷는 길 │
  │ 44+28  │               │ 가는 법 │            │ 목적지행  │        │ 낮·밤  │
  └────────┘               └────────┘            └──────────┘        └────────┘
       ▲                        │                      │                   │
       └────────────────────────┴──────────────────────┴───────────────────┘
                      어느 화면에서든 축제 아이콘 · 영문 전환
```

**핵심 동선은 상세 → 홈이다.** 관광지 상세의 `지금 여기서 가기`가 `?to=<id>` 주소를
만들고, 홈이 그 목적지로 다시 선다. 관광과 교통이 **한 번의 클릭으로** 이어지는
자리이며, 이 서비스의 차별점이 물리적으로 구현된 지점이다.

### 화면별로 내린 핵심 판단

**지금 여기 (`/`)**
- 위치를 허용하지 않거나 안동 밖이면 **안동역 기준**으로 똑같이 동작한다. 권한을
  거부한 사람도 서비스를 온전히 쓴다
- 검색창이 곧 목적지다. 비어 있으면 "지금 오는 버스", 채우면 "거기로 가는 버스"
- **거르지 않고 순서만 바꾼다.** 배차가 하루 3~13회인 외곽 노선에서 "지금 오는 차
  중 목적지행이 없다"는 흔한 상태이고, 그건 오류가 아니라 답이다
- 도착정보가 없는 기점·종점 승강장도 지우지 않는다 — 거기 선 사람에게는 "여기는
  안 뜬다"가 곧 정보다

**둘러보기 (`/browse`)**
- 인기순은 **한국관광공사 실제 방문 데이터**(LocgoHub `hubRank`)를 그대로 쓴다.
  우리가 임의로 매기지 않는다
- 찜닭·헛제삿밥을 이름으로 갈라낸다. 상류는 한식·카페로만 주는데, 그 분류로는
  "안동 식도락"에서 안동이 사라진다

**관광지 상세 (`/spots/[id]`)**
- 탈 노선·정거장 수·하차 후 도보 거리 + 운영시간·휴무일·주차·문의를 한 화면에
- `함께 많이 찾는 곳`은 거리가 아니라 **실제 방문 행동**이 근거다

**걷는 길 (`/walk`)**
- 버스와 무관한 화면이 아니다. **시작점까지는 타고 가야 하고 끝점에서는 타고
  돌아와야 한다** — 그래서 코스마다 버스 줄이 붙는다
- 야경 코스에 `막차 18:45, 해가 진 뒤엔 돌아오는 버스가 없다`를 함께 적는다

**안내 (`/about`)**
- 여기 적은 것은 **전부 코드가 실제로 하는 일이어야 한다.** 한 번 어긋난 적이 있고
  (ADR-024), 그래서 구조를 바꾸면 이 페이지부터 확인한다

## 4. 공모전 요구 ↔ 우리가 내세울 것

### 확인된 배점

| 항목 | 배점 | 우리가 대는 근거 |
|---|---|---|
| **서비스 완성도** | 30 | 화면 5개 + 영문 전 경로 실동작. API 16개 전부 200. 회귀 스크립트 4종. ADR 55건 |
| **기획력** | 30 | "차 없으면 무리"를 데이터로 반박. 관광→교통 한 번의 클릭. 대기시간을 여행 시간으로 |
| **데이터 활용 적절성** | 20 | 관광공사 **5종** + 안동시 2종 + 카카오맵. 원천을 가공 없이 쓰고 한계를 화면에 밝힘 |
| **미상** | 20 | ⚠️ 요강 원문 미확보. **추측으로 채우지 말 것** |

### ⚠️ 데이터 요건 (ADR-003이 인용)

> 데이터 활용은 한국관광공사 OpenAPI 형태만 인정되며, 단순 파일 데이터(Excel, CSV 등)
> 다운로드 활용은 인정되지 않아 심사에서 제외됩니다.

**원천 데이터는 파일로 박아 두지 않는다.** 전부 런타임 호출이다. 저장소의 정적 파일
(`route-stations.json` 등)은 **우리가 만든 가공 데이터**이고 ADR-003이 명시적으로
허용한 범주다. 성능을 이유로 API 응답을 커밋하지 않았다.

### 내세울 것 — 여섯

**① 관광과 교통이 갈라져 있던 것을 한 화면에서 잇는다**
안동버스정보앱은 버스만, 안동을담다·안동관광은 관광만 답한다. 44곳 **전부**에
`몇 번 버스로 몇 정거장, 내려서 몇 미터`를 답하는 것은 여기뿐이다.

**② 목적지를 정하면 화면이 그쪽으로 다시 선다**
지금 오는 차 중 목적지행을 앞으로 당기고, 걸어갈 수 있는 승강장을 다시 세우며,
기다리는 시간까지 더해 `지금 출발하면 총 몇 분`을 답한다.

**③ 버스가 끊겨도 남는 길을 따로 만들었다**
공공데이터에 없어 직접 짠 낮·밤 코스. 야경 코스에는 막차 경고를 함께 적는다.

**④ 질문을 뒤집는다 — "기다리는 동안 어디에 갈까"**
`다음 차 40분 뒤`에서 멈추지 않는다. 배차가 하루 3~13회인 지역에서 **대기시간은
여행의 예외가 아니라 기본값**이다.

**⑤ 모르는 것을 모른다고 말한다**
돌아오는 편 시각이 없으면 그렇게 적고, 도보 시간은 추정치라 `약`을 붙이고, 축제가
없는 날엔 아이콘이 사라진다. 영문도 `급행2`를 갈아치우지 않고 `Express 급행2`로
적어 현장에서 찾을 글자를 남긴다.

**⑥ 안내를 보는 데 계정이 필요 없다**
좌표가 브라우저 밖으로 나가지 않는다. 가까운 정류장을 고르는 계산까지 브라우저
안에서 끝낸다.

### 지역 특화 (안동에서만 성립하는 것)

1. 안동시 버스정보시스템 직접 연동 — 전국 서비스로는 확보 불가
2. 관광지 ↔ 정류장 매핑 직접 구축
3. 안동시 공개 운행시간표 반영
4. 안동 걷기길 직접 제작 (두루누비 수록 범위 밖)
5. 법정동 코드로 안동 데이터를 온전히 조회 — 지역 코드로는 관광지 누락·축제 0건

## 6. 기능설명서를 쓸 때 조심할 것

- **양식은 핵심 기능 최대 5개.** 지금 `지금 여기 · 둘러보기 · 관광지 상세 · 축제 ·
  영문`이 차 있고 **걷는 길이 빠져 있다.** 제안서는 이것을 1단계 4대 기능으로
  약속했다 — 넣으려면 하나를 빼야 한다
- **흐름도 캡처 20장이 옛 화면이다.** 슬라이드 6은 ②번이 "검색창에 목적지를 넣으면"
  이라고 말하는데 그림엔 검색창이 없다
- **슬라이드 4 이미지 6장이 자리표시자 그대로다.** 대표 썸네일 248×93
- **표는 좌표와 눈을 둘 다 봐야 한다.** 높이 수치가 그대로인데 글자만 잘린 적이 있다
- **제안서와 대조당한다.** 약속한 것이 사라졌으면 왜 사라졌는지 적어야 한다
  (두루누비가 그 사례이고, 근거를 적어 넣었다)
