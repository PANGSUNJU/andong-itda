## 2026-07-31 (금)

### 한 일
**개발 환경 복구**
- 경로 이전 후 `node_modules`가 없는 상태였다. pnpm 자체가 설치되어 있지 않아
  `npm i -g pnpm@10`(lockfile `9.0` 기준) 후 `pnpm install`
- pnpm 10이 esbuild의 build script를 차단한다고 경고하지만 무시해도 된다.
  `@esbuild/win32-x64`가 optional dependency로 이미 들어와 바이너리가 있다

**화면 구현 — 4개 페이지 전부**

| 경로 | 데이터 |
|---|---|
| `/` 지금 여기 | 위치 → 정류장 → 도착 + 도보권/버스권 관광지 + 인기 순위 |
| `/browse` 둘러보기 | `/api/spots` 64건 검색·분류·정렬 |
| `/spots/[id]` 상세 | 목록에서 조회 + `/api/spot-bus` 결합 |
| `/walk` 걷는 길 | 정적 코스 2개 |

- 디자인 토큰만 쓴다. 컴포넌트에서 색·라운드 값을 직접 쓰지 않았다
- 큰 타이포(`text-arrival`)는 도착 분 표시 두 곳에만 썼다
- 찜하기는 넣지 않았다 (ADR-014)

**화면을 위해 추가한 서버 라우트 2개**
- `/api/bus/nearby-stations` — 정류장 전체가 **1.86MB**다. 브라우저로 내려보내
  거기서 최근접을 고를 수 없다. 거리 계산을 서버에서 끝낸다
- `/api/spots/nearby` — 하버사인을 클라이언트에 두 번째로 구현하지 않기 위해서다

### 알게 된 것
- **같은 이름의 정류장이 서로 다른 stationId로 여러 개 있다.**
  "안동역(안동터미널)"이 354000416 / 354000459 / 354000536 셋이다(방향별 승강장).
  가장 가까운 승강장이 내가 갈 방향이라는 보장이 없어 **정류장 전환 UI가 필수**다.
  상류가 같은 stationId를 중복으로 주기도 한다 → nearby-stations에서 dedupe
- **안동역 반경 2km 안에 관광지가 2곳뿐이다.** 도보권만 보여주면 홈의 핵심 띠가
  빈다. 반경을 넓게 한 번 불러 화면에서 도보권/버스권으로 나눈다
- 4.4km 떨어진 곳에 "걸어서 약 66분"을 붙이면 버스를 타야 한다는 사실을 가린다.
  도보 시간은 2km 이내에서만 표시한다
- **중심관광지 목록에 골프장·영화관이 섞여 있다.** 남안동CC·안동레이크GC·리버힐CC·
  CGV/안동·롯데시네마. 방문 데이터 기반이라 당연한 결과지만 여행자 목록으로는 노이즈다
- 이름에 상태가 박힌 항목이 있다 — "낙강물길공원/공사중(2028년12월31일개장예정)"

- `pnpm install`은 성공했으나 `pnpm dev`에서 `nuxt` 실행 파일을 찾지 못함
- 원인: 프로젝트 경로에 한글이 포함되어 `node_modules/.bin` 심볼릭 링크가 생성되지 않음
- 영문 경로로 이전 + `node_modules` 재설치로 해결 → ADR-017

**정류장 ID 검증**
- 하회 `354000701`(들어오는 편) → 210번 25분 후 도착 확인, `via: 교보생명 -> 하회마을`
- 하회 `354002046`(나가는 편) → 빈 배열 반환
- 월영교 `354000716` 확인 (112번 7번째 정류장, 교보생명에서 3,386m)
- 법흥동 `354000064` 확인 (임청각·법흥사지 칠층전탑 인접)

**112번 노선 정보 확보**
- 정류장 14개, 총 7,146m, 기점 교보생명 / 종점 리첼호텔건너
- `stTm`·`edTm`·`maxInterval`·`minInterval`·`runCnt` 필드 전부 null
- `runTotCnt: 0` 확인 → 호출 시점에 운행 종료 상태

**서버 API 구현 — 라우트 5개**

| 라우트 | 캐시 | 검증 |
|---|---|---|
| `GET /api/bus/stations` | 1일 | 2107건, 전부 `useYn: 'Y'` |
| `GET /api/bus/arrivals?stationId=` | 없음 | 정렬·400·빈배열 확인 |
| `GET /api/bus/routes` | 1분 | 421건, 운행 중 52개 |
| `GET /api/spot-bus/[spot]` | 없음 | 관광지 7곳 + 404 2종 |
| `GET /api/spots` | 1일 | 64건 중 19건 병합 |

- 공용 유틸 2개: `server/utils/andongBus.ts`, `server/utils/tourApi.ts`
- 외부 API 실패는 전부 **502 + 원인**으로 감싼다. 타임아웃 10초.
  502 경로는 타임아웃을 1ms로 일시 강제해 실제로 확인했다.
- 프로덕션 빌드(`.output`)에서도 5개 라우트 전부 실호출 검증

**막힌 것 — TourAPI 401**
- 원인은 키가 아니라 **이중 인코딩**이었다. `.env`의 키가 Encoding 형태(96자)라
  쿼리 직렬화 때 한 번 더 인코딩돼 `%`가 `%25`가 됐다 → ADR-018
- 해결: 키를 한 번 디코딩해두고 인코딩은 직렬화에 한 번만 맡긴다.
  Encoding 키든 Decoding 키든 그대로 동작한다.

**회귀 검증 스크립트 2개** (프레임워크 없이 `node`로 바로 실행)
- `node scripts/check-bus-logic.ts` — 도착 정렬(null 후순위) · 운행상태 3분기
- `node scripts/check-spot-match.ts` — 이름 정규화 · 유사도 · 거리 · 좌표 1순위 매칭

### 알게 된 것
- Nuxt 4는 소스 루트가 `app/` 하위다. `server/`는 여전히 루트에 위치한다.
- 기점 정류장은 도착정보 조회가 원리적으로 불가능하다 → ADR-015
- 안동시가 노선 시간표 필드를 입력하지 않았으므로 첫차·막차는 정적 데이터에 의존해야 한다
- **버스 API가 http에서 https로 302 리다이렉트한다.** 지시서 기준과 다르다 → ADR-019
- **`baseYm=202607`이 7월 말에도 0건이다.** "매월 8일 갱신"을 믿으면 빈 화면이 된다.
  최대 3개월 뒤로 폴백한다 → ADR-021
- **KorService2 결측 범위가 문서보다 넓다.** 하회마을·도산서원·월영교뿐 아니라
  병산서원·봉정사·안동역·만휴정·부용대도 없다. 인기 상위 6곳이 전부 이미지 없이 표시된다
- **`hubRank`는 매월 바뀐다.** 202606 기준 1위는 하회마을이 아니라 월영교다.
  순위를 하드코딩하면 안 된다
- 좌표만으로 매칭하면 틀린다. 안동시립박물관의 최근접 항목은 1m 거리의 "안동민속촌"이었다
- 두 정적 데이터가 서로 어긋난다. `timetable-spots.json`(파싱 원본)과
  `spot-station-map.json`(정리본) 중 후자만 런타임 소스로 쓴다 → ADR-020

### 결정한 것
- ADR-015 관광지 정류장 방향별 ID 매핑
- ADR-016 버스 시간표 정적 파일 활용
- ADR-017 개발 경로 영문 유지
- **ADR-007 번복** — 막차 안내 "제외"에서 "실시간 3단 결합으로 구현"으로
- ADR-018 인증키는 한 번 디코딩해서 사용
- ADR-019 버스 API는 https 직접 호출
- ADR-020 시간표 소스는 `spot-station-map.json` 단일화
- ADR-021 관광 API 조인은 좌표 1순위 + 이름 게이트(200m / 0.4)

- 안동 지역코드 확인: `areaCode=35`, `sigunguCode=11`

- 100건 조회 성공. 하회마을 1위, 월영교 2위, 도산서원 4위 등 핵심 관광지 전부 포함

**음식점 / 축제 데이터 확인**
- 음식점(39) 16건. 헛제삿밥·찜닭·간고등어 등 향토음식 모두 포함 → ADR-011
- 축제(15) **0건**. 중심관광지 API에는 존재하나 국문 관광정보에는 미등록 → ADR-010

### 알게 된 것
- API마다 지역 코드 체계와 파라미터 명명이 제각각이다. 문서를 믿기 전에 호출해봐야 한다.
- 같은 대상이라도 API에 따라 존재 여부가 다르다.
  하회마을은 국문 관광정보에 없고 중심관광지에 있으며,
  안동 축제는 중심관광지에 있고 국문 관광정보에 없다.
  **하나의 API만 믿고 설계하면 안 된다.**
