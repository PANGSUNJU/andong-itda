### 실측 (전부 오늘 실호출)

`searchFestival2` + 법정동 코드 → **7건, 203ms, 이미지 7/7 = 100%**.
관광지가 76%인 것에 비하면 데이터가 깨끗하다. 좌표·주소도 7건 전부 있다.

축제장에서 가장 가까운 정류장을 계산해 봤다. **7건 전부 400m 이내다.**

| 축제 | 최근접 정류장 | 거리 |
|---|---|---|
| 안동국제탈춤페스티벌 | 탈춤공원건너 | 97m |
| 차전장군 노국공주축제 | 구 안동역 | 126m |

오늘 응답: 7건 중 **2건**이 남는다(K-스토리 D-16, 탈춤 D-23). 안아드림은 D-31이라
30일 창 밖이다. 9/20에는 탈춤 D-4와 안아드림 D-12로 2건이 된다.

### 알게 된 것

**1. `eventStartDate`는 "그 기간에 시작하는"이다.** 필수 파라미터인데
`eventStartDate=오늘`로 주면 0건이 온다. 진행 중인 축제조차 안 나온다.
넓게 받아서 우리가 거르는 것 말고 다른 방법이 없다.

**2. `progresstype`·`festivaltype`은 쓸 수 없다.** 이름만 보면 진행 상태를 줄 것
같은데 실제 값은 "선택안함" 아니면 빈 문자열이고 `festivaltype`은 7건 전부 빈
값이다. 날짜로 판정해야 한다.

**3. ADR-010이 남긴 "향후" 제안도 틀렸다.** "중심관광지 API의 축제 항목을
활용한다"고 적으면서 "차전장군노국공주축제가 54위로 있다"를 근거로 들었는데,
오늘 `/api/spots` 54곳에 축제는 **0건**이다. 분류 분포도 문화관광 21 · 역사관광
17 · 레저스포츠 5 · 기타관광 4 · 쇼핑 3 · 자연관광 2 · 체험관광 2로 축제가 없다.
LocgoHub는 축제를 주지 않는다.

**4. 탈춤공원 두 승강장의 영문명이 같다.** `탈춤공원건너`(97m)와 `탈춤공원앞`(98m)이
`stationEngNm`으로는 **둘 다 `Talchum gong-won`**이다. 거리도 1m 차이라 영문
화면에서 칩 두 개가 글자 그대로 구별되지 않았다. 처음엔 이름과 거리만 칩에 넣었다가
응답을 눈으로 보고서야 알았다. 방면(`direction`)을 붙여서 갈랐다 —
건너는 청소년수련관쉼터 방면, 앞은 법원.검찰청 방면이다. 홈이 이미 같은 이유로
같은 처방을 쓰고 있었다.

**5. 오늘을 KST로 계산해야 한다.** 배포는 UTC라 `new Date().toISOString()`을
그대로 쓰면 KST 09-24 00:30이 UTC로는 09-23이다. 탈춤페스티벌이 시작하는 바로 그
순간에 "D-1"이라 적힌다. 축제는 이 서비스에서 날짜에 의존하는 유일한 데이터라
이 오차가 여기서만 난다.

### 한 일
**`/api/spots` 콜드스타트를 고쳤다.** 배포 전 필수로 적혀 있던 유일한 성능 항목이다.

원인이 성능이 아니었다. **조회 파라미터였다.** KorService2는 지역 필터를 두 벌
받는데(`areaCode`/`sigunguCode` vs `lDongRegnCd`/`lDongSignguCd`) 우리가 쓰던 쪽이
좁았다. 넓은 쪽으로 바꾸니 관광지가 63건 → 107건이 되고, 그동안 "없다"고 알고
있던 하회마을·도산서원·월영교·병산서원·봉정사·만휴정이 전부 목록에 들어왔다.

없는 것을 이름으로 하나씩 찾아다니던 호출이 통째로 필요 없어졌다.

|---|---|---|
| 첫 요청 (4회 실측) | 2.76 / 2.89 / 4.09 / **12.61**초 | 1.71 / 1.74 / 1.75 / 1.84초 |
| 응답 내용 | 54곳 · 이미지 41 · 영문 17 | **동일** |

→ ADR-034

**응답을 대조했다.** 성능만 보고 넘기면 조용히 데이터가 빠질 수 있어서 옛 버전을

`contentid`, 같은 사진 URL, 같은 영문명이었다. 차이는 한 건 —
안동군자마을이 `Andong Gunja Village (Ocheon Historic Site)`로 나오는데,
괄호 안 영문 주석은 이름의 일부라 남기기로 ADR-033이 이미 정해 둔 쪽이다.

**회귀 스크립트에 `pickByName`을 고정했다.** 2차 매칭이 하회마을 본체(1,580m,
유사도 1.00)를 고르고 겸암정사(585m, 0.9)를 안 고르는 것, 후보 배열 순서를
뒤집어도 같은 것, 본체가 없으면 겸암정사도 안 붙는 것까지 5개.

### 알게 된 것
**고친 것은 중앙값이 아니라 꼬리다.** 옛 방식 중앙값은 3.5초였고 그것만 보면
10초 제한에 여유가 있어 보인다. 그런데 4회 중 1회가 12.6초였다. 호출이 수십
회면 "가장 느린 한 번"에 걸릴 확률이 누적된다. 호출을 줄이자 **분산이 함께
사라졌다**(1.71~1.84초). 문서에 적힌 11초는 과장이 아니라 그 꼬리의 기록이었다.

**`lDongSignguCd`는 `170`이다.** LocgoHub는 같은 법정동 코드를 `47170`으로 받는다.
여기에 `47170`을 주면 **오류 없이 조용히 0건**이 온다. 상수 두 개가 같은 체계의
다른 자릿수라 섞기 쉽고, 섞으면 목록이 통째로 비면서 에러도 안 난다.

**영문명 3단계(ADR-033)가 통째로 사라졌다.** 남은 37곳에 40회를 더 쓰던 이름
재검색이 **0곳**을 더 찾았다. 법정동 조회 1회가 옛 3단계와 같은 17곳을 준다.
옛 두 경로가 주는 레코드가 새 조회에 전부 포함되는 것을 레코드 수로 확인했다
(52 + 57 = 57).

**같은 오진 위에 우회로를 네 번 쌓았다.** ADR-004(없다) → 08-02(이름으로 찾자)
→ ADR-022(이미지 보충) → ADR-033(영문명 3단계). 넷 다 "상류 데이터 결함"으로
진단했는데, 그 결함을 비껴가는 문이 **같은 API에 처음부터 열려 있었다.**
증상이 재현되면 처방부터 만들지 말고 조회 조건을 먼저 의심할 것.

### 안 한 것
- **음식점을 안 옮겼다.** 같이 옮기면 15건 → 27건이 된다. 늘어나는 12곳의 이름을
  보고 향토음식 태깅(ADR-023)이 성립하는지 확인해야 한다. 콜드스타트를 고치는
  작업에 데이터 범위 변경을 얹으면 나중에 무엇이 화면을 바꿨는지 못 가른다.
- **축제를 안 붙였다.** 같은 조회로 7건이 온다. ADR-010("0건이라 제외")은 번복
  대상이지만 그건 기능 추가라 별도로 한다.

### 발견한 것 (이번 변경과 무관)
안동호반자연휴양림과 그 방문자센터가 같은 `contentid 2436209`에 붙어 사진이
겹친다. 옛 응답에도 똑같이 있었다. LocgoHub가 한 시설을 두 항목으로 등재한 자리다.

**디버그 라우트 `/api/test` 제거** — 인증키 주입 확인용 임시 라우트였는데
프로덕션 빌드(`.output`)에까지 들어가 있었다. 키 값은 아니지만 키의 존재 여부와

**이미지 결측 실측** — "완성도가 떨어진다"는 체감의 정체를 숫자로 확인했다.

| | 건수 | 비율 |
|---|---|---|
| 이미지 보유 | 18 / 64 | 28% |
| 이미지 결측 | 46 / 64 | **72%** |

문제는 결측률 자체가 아니라 **분포**다. 이미지가 있는 18곳이 전부 순위 12위
이하다. **인기 1~11위는 이미지가 하나도 없다.** 첫 화면 최상단 카드가 전부
폴백이라 "데이터가 빈 서비스"로 보인다.

### 알게 된 것
**결측이 아니라 조회 방식의 문제였다.** 그동안 "하회마을·도산서원·월영교는
KorService2에 없다"(ADR-004)고 알고 있었는데, `searchKeyword2`로 이름을 직접
검색하면 **전부 있고 이미지도 전부 있다.**

없는 게 아니라 **`areacode`·`sigungucode`가 빈 값**이라
`areaBasedList2`(지역 기반 조회)에 안 잡히는 것이다. 한국관광공사 쪽 데이터 결함이다.

```
하회마을 [유네스코 세계유산]   contentid 894027   areacode ''  firstimage 있음
도산서원 [유네스코 세계유산]   contentid 126200   areacode ''  firstimage 있음
월영교                        contentid 988449   areacode ''  firstimage 있음
병산서원 [유네스코 세계유산]   contentid 126227   areacode ''  firstimage 있음
봉정사   [유네스코 세계유산]   contentid 126158   areacode ''  firstimage 있음
만휴정                        contentid 126998   areacode ''  firstimage 있음
```

→ **지역 기반 조회 하나만 믿으면 안 된다.** 07-23에 "하나의 API만 믿고 설계하면
안 된다"고 적었는데, 같은 API 안에서도 조회 방식에 따라 존재 여부가 갈린다.

**보충 시뮬레이션 결과 46건 중 21건이 채워진다 (28% → 61%).**
1·3·4·5·9·11위가 전부 채워져 첫 화면 체감이 바뀐다.

**거리만으로 고르면 틀린다 — ADR-021의 함정이 그대로 재현됐다.**
`안동하회마을`의 최근접 후보는 585m의 "안동 하회마을 **겸암정사**"였다.
정작 본체인 "안동 하회마을 [유네스코 세계유산]"은 1,580m로 더 멀다.

두 가지를 고쳐야 정답이 나온다.
- `normalizeSpotName`이 괄호는 떼는데 **대괄호는 안 뗀다.**
  `[유네스코 세계유산]`이 남아 완전일치가 포함관계(0.9)로 떨어진다
- 키워드 보충에서는 **유사도가 1순위, 거리가 2순위**여야 한다.
  이름으로 검색해 온 후보이므로 이름이 주 증거고 거리는 위생 검사다

| 후보 | 거리 | 현행 | 대괄호 제거 후 |
|---|---|---|---|
| 안동 하회마을 겸암정사 | 585m | 0.90 | 0.90 |
| 안동 하회마을 [유네스코 세계유산] | 1,580m | 0.90 | **1.00** |

거리 게이트 자체는 유효하다. `CGV/안동`의 최근접 후보가 185km 떨어진
"CGV 강남점"이었고 게이트가 걸러냈다.

**끝내 채울 수 없는 25건의 성격이 갈린다.**
- 교통 시설 — 안동역, 안동터미널, 옹천역/폐역
- 체육·상업 시설 — 남안동CC, 안동레이크GC, 리버힐CC, CGV/안동, 롯데시네마,
  안동드림베이스볼파크, 용상체육공원/야구장, 안동시생활체육공원, 안동강변구장
- 진짜 관광지인데 없는 곳 — 부용대, 화천서원, 안동문화관광단지, 천지갑산, 안동루

앞의 두 부류는 이미지가 없는 게 정상이다. **애초에 여행자 목록에 있으면 안 된다.**
노이즈 필터(아래 할 일)와 이미지 결측이 같은 문제의 두 얼굴이었다.

### 그래서 한 일 — 이미지 보충 + 노이즈 필터

**`searchKeyword2` 이미지 보충** (`backfillImages`)

지역 조회로 병합한 뒤, 그래도 이미지가 없는 것만 이름으로 재검색한다.
검색어는 최대 2개(`안동하회마을`, `하회마을`)로 묶고 완전일치가 나오면 끊는다.

매칭은 **유사도 1순위, 거리 2순위**다. 거리만 보면 하회마을에 겸암정사가 붙는다.
게이트는 유사도에 따라 다르게 준다.

| 유사도 | 반경 | 이유 |
|---|---|---|
| 1.0 완전일치 | 3km | 두 API의 대표 좌표가 다른 지점을 가리킨다. 하회마을이 1,580m 벌어진다 |
| 0.9 포함관계 | 500m | 이름이 더 길다는 건 다른 장소일 수 있다는 뜻. 585m의 겸암정사를 막는다 |
| 그 미만 | 기각 | |

`normalizeSpotName`이 대괄호를 떼도록 고쳤다. 이게 핵심이었다.
`[유네스코 세계유산]`이 남아 있으면 완전일치가 0.9로 떨어져 겸암정사와 동점이 된다.

**노이즈 필터** (`noiseReason`) — ADR-022. 이름 패턴으로 자른다.
카테고리로 자르면 CGV와 하회세계탈박물관이 같이 날아간다(둘 다 '문화관광').

### 결과

| | 전 | 후 |
|---|---|---|
| 관광지 건수 | 64 | **49** (노이즈 15건 제외, 오탐 0) |
| 이미지 보유 | 18 (28%) | **37 (76%)** |
| 인기 1~11위 이미지 | 0곳 | **9곳** (남은 2곳은 부용대·화천서원) |
| `/api/spots` 첫 요청 | — | 11초 (보충 전 값은 측정 안 함) |

하회마을이 `contentId 894027`(본체)로 붙은 것까지 확인했다. 겸암정사(1180879) 아니다.

### 알게 된 것
**노이즈 필터가 이미지 결측을 같이 해결한다.** 제외한 15건 중 14건이 이미지가
없던 항목이었다. 역과 골프장에 관광 사진이 없는 게 정상이다.
보충 대상이 줄어 첫 요청도 16초 → 11초로 짧아졌다.

**Nitro 캐시가 `.nuxt/cache/`에 파일로 남아 재빌드해도 살아남는다.**
보충 코드를 넣고 빌드했는데 응답이 28% 그대로여서 한참 헤맸다.
`defineCachedEventHandler`의 `maxAge: 1일`이 디스크에 그대로 있었다.

**동시 실행 수를 안 정하면 못 쓴다.** TourAPI 한 번이 2~3초다.
순차 → 2분 초과, 6 → 31초, 12 → 16초. 그 이상은 더 줄지 않는다.

### 막힌 것 — 첫 요청 11초
캐시가 빈 첫 요청이 서버리스 함수 제한을 넘길 수 있다.
그 요청이 타임아웃되면 **캐시가 영영 안 채워진다.** 배포 전에 옮겨야 한다.
빌드 타임 생성이나 스케줄 워밍 중 하나인데 아직 안 정했다.

## `/api/food` 사전 조사 (2026-08-02)

다음 작업이라 데이터부터 확인했다. **코드를 쓰기 전에 확인한 게 맞았다.**
"이미지 보충 로직을 그대로 재사용하면 된다"고 생각했는데 **틀렸다.**

### 실측 — ADR-011 수치가 그대로 재현된다
`contentTypeId=39`, `areaCode=35&sigunguCode=11` → **16건**.

| | 건수 |
|---|---|
| 이미지 있음 | 9 (56%) |
| 이미지 없음 | **7 (44%)** |
| `lclsSystm2=FD01` 한식 | 11 |
| `lclsSystm2=FD05` 카페 | 5 |

`cat3`는 `A05020100`(한식) / `A05020900`(카페) 두 값뿐이고 `lclsSystm2`와 1:1이다.
둘 중 아무거나 써도 된다.

### 알게 된 것 1 — 이미지 보충이 음식점에는 안 먹힌다 (0/7)
결측 7곳 전부 `searchKeyword2`에서 후보 0건이다.
`안동한우갈비`만 후보 1건이 나왔는데 거리 게이트에서 기각됐다(다른 지역 동명 업소).

관광지와 **원인이 다르기 때문이다.**

| | 관광지 | 음식점 |
|---|---|---|
| 지역 조회에 잡히나 | ❌ (`areacode` 빈 값) | ✅ 잡힌다 |
| 이름 검색하면 | ✅ 이미지까지 있다 | 같은 레코드가 나온다 |
| 결측의 정체 | **조회 방식 문제** | **진짜로 없다** |

관광지는 "이미지 있는 레코드가 다른 곳에 있었다"였고, 음식점은 "그 레코드에
이미지가 없다"다. 조회를 몇 번 하든 없는 건 없다.
**음식점 이미지 44% 결측은 폴백이 유일한 답이다.** `SpotPhoto`가 이미 그렇게 돼 있다.

### 알게 된 것 2 — `tel`이 16건 전부 빈 값이다
`FoodPlace.tel`을 정의해 뒀는데 `areaBasedList2`는 전화번호를 안 준다.
채우려면 `detailCommon2`가 필요한데 그건 아직 미검증이다(`/api/spots/[id]`와 같은 벽).
**전화 걸기 버튼을 화면에 넣지 말 것.** 넣으면 16곳 전부 빈 버튼이 된다.

### 알게 된 것 3 — 향토음식 분류를 API가 주지 않는다
`FoodPlace.foodCategory`를 `'찜닭' | '헛제삿밥' | '간고등어·한식' | '카페·베이커리'`로
적어 뒀는데, **API가 주는 구분은 한식/카페 둘뿐이다.**

이름으로 알 수 있는 것과 없는 것이 갈린다.

| 분류 | 업소 | 이름으로 판별 |
|---|---|---|
| 헛제삿밥 | 맛50년 헛제사밥, 헛제사밥까치구멍집 | ✅ |
| 찜닭 | 안동 유진찜닭 | ✅ |
| 간고등어 | 옥야식당, 일직식당 | ❌ 이름에 안 드러난다 |

ADR-011의 분류표는 **API가 아니라 사람이 아는 사실로 만든 것**이다.
옥야식당이 간고등어집이라는 정보는 응답 어디에도 없다.

선택지는 셋이다. **결정 필요.**
1. 한식/카페 2분류만 쓴다 — 정직하지만 "안동 향토음식"이라는 색이 사라진다
2. 이름 패턴으로 찜닭·헛제삿밥만 추가 태깅, 나머지는 '한식' — 부분적
3. 16곳짜리 정적 매핑을 직접 만든다 — 정확하지만 손으로 관리해야 한다

`spot-station-map.json` 선례가 있으니 3번이 이 프로젝트답긴 하다.
다만 그건 "임의로 채우지 말 것"이라는 조건이 붙어 있었다.

### 그래서 `/api/food`에 해야 할 일

## `/api/food` 구현 (2026-08-02)

사전 조사에서 남겨둔 분류 결정을 **2안(이름 패턴 + API 2분류)으로 확정**하고
라우트와 화면을 붙였다. → ADR-023

### 결정의 기준은 정확도가 아니라 근거의 소재였다
3안(정적 매핑)이 제일 정확하다. `spot-station-map.json` 선례도 있다.
그런데 그 선례에는 "임의로 채우지 말 것"이 붙어 있었고, 그건 **좌표로 검증할 수
있어서** 지킬 수 있는 조건이었다. 옥야식당이 간고등어집이라는 사실에는
대조할 원본이 없다. 검증 못 하는 사실을 코드에 박으면 다음 사람은 출처를 모른다.

그래서 **응답만 보고 다시 만들 수 있는 것만** 넣었다.

```
찜닭     1   title에 '찜닭'
헛제삿밥 2   title에 '헛제사밥' — 상호 표기는 사이시옷이 없다. 둘 다 받는다
한식     8   cat3 A05020100 (옥야식당·일직식당 포함)
카페     5   cat3 A05020900
```

**옥야식당이 '한식'인 건 버그가 아니라 결정이다.** 여기를 고치고 싶어지면
그 근거가 응답 밖에 있다는 뜻이다. `check-spot-match.ts`에 그 문장을 주석으로
박아 두고 회귀로 잡는다.

### `/api/food`는 `/api/spots`보다 훨씬 단순하다
| | `/api/spots` | `/api/food` |
|---|---|---|
| 소스 | 2개 병합 | KorService2 단독 |
| 순위 | `hubRank` | 없다 |
| 이미지 보충 | 46건 중 21건 | 안 한다 |
| 첫 요청 | 약 11초 | **2~3초** |

병합할 상대도, 보충할 방법도 없으니 호출 한 번이면 끝난다.
사전 조사에서 "재사용하면 된다"고 생각했던 그 로직을 **안 붙인 것**이
이번 구현에서 가장 중요한 판단이다.

### 화면에서 갈린 것들
- **순위가 없으니 "인기순" 토글도 없다.** 없는 축을 비활성 버튼으로 남기지 않는다.
  기본 정렬은 분류 순서고 향토음식이 앞이다
- **칩을 상수에서 만든다.** 관광지 탭과 반대다. 거기는 분류가 상류의 것이라
  응답에서 만들었고, 여기는 우리가 정의한 닫힌 집합이다. 0건인 분류는 안 띄운다
- **칩 선택을 탭마다 따로 뒀다.** 하나로 묶으면 '역사관광'을 고른 채 식도락으로
  넘어갔을 때 사용자가 건 적 없는 필터로 0곳이 뜬다
- **카드에 링크를 안 붙였다**(`:to="null"`). `/spots/[id]`는 `/api/spots`에서 id를
  찾는데 음식점은 거기 없어 404다. 갈 곳 없는 링크를 만들지 않는다
- 사진 없는 카드가 7곳이라 목록 아래에 한 줄 적었다. 폴백이 고장으로 보이면 안 된다

### `FoodPlace.tel`은 비워 두는 게 아니라 지웠다
사전 조사에서 "비워 둔다"고 적었는데 그러면 다음 사람이 필드를 보고 전화 버튼을
만든다. **없는 필드는 화면이 못 쓴다.** 지우고 왜 없는지를 타입 주석에 남겼다.

### 검증
```
GET /api/food                 16건 · 찜닭1 헛제삿밥2 한식8 카페5
/browse 식도락 탭 SSR         카드 16개(전부 링크 없음) · 칩 5개 · 폴백 7개
node scripts/check-spot-match.ts   ok (foodCategoryOf 11건 추가)
```

### 곁가지 정리 — `region.ts` 죽은 상수 제거
`FALLBACK_LOCATION`(정본과 4,838m 어긋남)과 `WALK`를 지웠다.
`FOOD_CATEGORY`는 실제로 쓰면서 `FOOD_CAT3`로 이름을 바꿨다.
"카테고리"가 아니라 **cat3 코드**이고, 향토음식 분류는 여기 없다는 걸
이름이 말하게 했다.

### 곁가지로 발견한 것 — `region.ts`에 위험한 죽은 코드가 있다
`FALLBACK_LOCATION`과 `WALK`가 **아무 데서도 참조되지 않는다.**
07-31에 `location.ts`를 만들면서 `ANDONG_ORIGIN`·`WALK_METERS_PER_MINUTE`로
옮겼는데 원본을 안 지웠다.

단순 중복이면 넘어가도 되는데 **값이 다르다.**

```
FALLBACK_LOCATION  36.5606,  128.7274    ← region.ts (죽은 코드)
ANDONG_ORIGIN      36.57349, 128.67566   ← location.ts (실사용)
                   4,838m 차이
```

`location.ts` 쪽이 맞다. 정류장 354000536의 실좌표이고, 2020년 이전한 송현동
역이다. `region.ts` 쪽은 출처 불명이고 구 안동역 근처도 아니다.

지금은 아무도 안 써서 무해하지만, 이름이 그럴듯해서 **다음에 누가 임포트하면
5km 떨어진 곳을 기준으로 "가장 가까운 정류장"을 계산한다.** 지우는 게 맞다.
→ `/api/food` 작업에서 지웠다(위).

## 지도 구현 (2026-08-02)

카카오 JavaScript 키를 발급받아 `MapCard`에 실제 지도를 붙였다. 세 자리가
한 번에 살아난다 — 홈 도보 반경, 둘러보기 분포, 상세 주변.

### 키만 넣으면 지금보다 나빠지는 상태였다
`MapCard`에는 "키가 없을 때 안내를 그리는 분기"만 있었다. 키가 채워지면 그
분기가 꺼지면서 **아무것도 안 그린다.** 세 자리가 전부 빈 회색 상자가 된다.
키 등록과 SDK 구현이 같이 가야 하는 이유였다.

### 도메인 등록이 안 되면 키가 있어도 401이다
실측으로 확인했다.

```
GET https://dapi.kakao.com/v2/maps/sdk.js?appkey=...&autoload=false
Referer: http://localhost:3123
→ 401 {"errorType":"AccessDeniedError",
       "message":"domain mismatched! caller=http://localhost:3123."}
```

**포트까지 본다.** `localhost:3000`을 등록해 두고 3123으로 띄우면 안 뜬다.
그리고 이 실패는 **조용하다.** 스크립트 태그가 401을 받으면 콘솔에만 남는다.
그래서 `script.onerror`를 잡아 화면 문구를 갈랐다.

| 상태 | 문구 |
|---|---|
| 키 없음 | 지도 준비 중 |
| 로드 실패(도메인 미등록 등) | 지도를 불러오지 못했어요 |

둘을 같은 말로 덮으면 "아직 안 붙인 것"과 "붙였는데 안 되는 것"을 구분 못 한다.

### 조작을 껐다
`draggable: false` + `setZoomable(false)`. 기능을 아낀 게 아니라 **스크롤을 지킨 것**이다.
카드 안 지도가 모바일에서 페이지 스크롤을 먹으면 아래 목록으로 못 내려간다.
ADR-013이 "전면 지도 UI를 안 쓴다"고 한 이유와 같은 선상이다.

### ADR-013에서 하나 빠졌다 — 리스트↔지도 토글
안 만들었다. 우측 지도가 상시 노출되고 **목록 필터를 그대로 따라가기** 때문이다.
칩으로 '카페'만 걸러 놓으면 지도에도 5곳만 남는다. 토글은 두 화면이 서로 다른
것을 보여줄 때 필요한 장치인데, 여기서는 둘이 같은 것을 본다.

지도가 전체를 그리게 두는 선택지도 있었지만 그러면 목록과 지도가 다른 말을 한다.
그때는 둘 다 못 믿는다.

### SDK 로더를 컴포넌트 밖으로 뺐다
`MapCard`는 한 화면에 여러 개 뜰 수 있다. 컴포넌트마다 script를 붙이면 SDK가
중복 로드된다. 프로미스를 모듈 스코프에 캐시해 첫 호출만 실제로 받는다.
`autoload=false`로 로드와 초기화를 분리해야 `maps.load()` 콜백을 걸 수 있다.

### 검증
```
지도 미표시 상태(키 없음)   4개 화면 SSR 200
SDK 401 재현               도메인 미등록 확인 (위)
실물 렌더                  ❌ 아직 — 도메인 등록 후 확인 필요
```

**실제로 지도가 그려지는 것은 아직 못 봤다.** 콘솔에 도메인을 등록해야 확인된다.

- 100건 조회 성공. 하회마을 1위, 월영교 2위, 도산서원 4위 등 핵심 관광지 전부 포함
- `hubRank` 필드로 실제 방문 기반 순위 확보

**음식점 / 축제 데이터 확인**
- 음식점(39) 16건. 헛제삿밥·찜닭·간고등어 등 향토음식 모두 포함 → ADR-011
- 축제(15) **0건**. 중심관광지 API에는 존재하나 국문 관광정보에는 미등록 → ADR-010

### 알게 된 것
- API마다 지역 코드 체계와 파라미터 명명이 제각각이다. 문서를 믿기 전에 호출해봐야 한다.
- 같은 대상이라도 API에 따라 존재 여부가 다르다.
  하회마을은 국문 관광정보에 없고 중심관광지에 있으며,
  안동 축제는 중심관광지에 있고 국문 관광정보에 없다.
  **하나의 API만 믿고 설계하면 안 된다.**

### 결정한 것
ADR-001 ~ ADR-014 작성.
백엔드/DB 미사용, 서버 프록시 경유, 중심관광지 API를 데이터 뼈대로 채택,
화면 구조 4개 페이지 확정, 지도 도입 범위 한정, 찜하기 후순위 이관 등.
